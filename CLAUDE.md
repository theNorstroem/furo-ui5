## What this package is

`@furo/ui5` extends SAP's [`@ui5/webcomponents`](https://sap.github.io/ui5-webcomponents/) with a `bindData(fieldNode)` interface on top of `@furo/open-models`. Each Furo component subclasses the corresponding UI5 component and adds data-binding, FAT/meta/constraint handling, and value-state management — UI5 component APIs/events are inherited unchanged. The package ships JSX intrinsic types, a custom-elements manifest, and `web-types.json` for IDE completion against the wrapped components.

## Commands

- `npm start` — vite dev server (port 8080) + tsc watch. Loads `index.html` linking to `dev-playground/*.html` sandboxes. `/api/*` is proxied to `localhost:7070/api`.
- `npm test` / `npm run test:watch` / `npm run test:ui` — vitest **in a real Chromium browser** (`@vitest/browser` + Playwright). Spec files live in `test/*.spec.ts` (note: `include: ["test/**/*.spec.ts"]` in `vite.config.ts` — `src/**/*.spec.ts` is NOT picked up). Run a single file: `npx vitest run test/TextInput.spec.ts`.
- `npm run lint` / `npm run lint:fix` — eslint with full type-checking (strict-type-checked + stylistic-type-checked + lit + lit-a11y + wc plugins).
- `npm run build` — full pipeline: `analyze` (public CEM) → `analyze:internal` → `analyze:deep` (writes/validates `web-types.json`) → `gen:intrinsic` (regenerates `src/JSX/*` from CEM) → `tsc` → `tsc-alias` (rewrites `@/*` imports in the emitted `dist/`).
- `npm run gen:contracts` — regenerates `src/models/` from `.proto` files via `contracts/protoc-gen-open-models.sh` (requires `protoc` + the `open-models` plugin on PATH). The shell script reads from `contracts/proto` and `contracts/proto_dependencies` despite still naming `proto/` internally — run it from the repo root.
- `npm run storybook` — Storybook 10 on port 6006 (stories in `src/stories/**`).

The husky `pre-commit` hook runs `npm run lint` and aborts if lint modifies files that weren't already staged — stage fixes before committing.

## Architecture

### Component shape (the pattern every web-component follows)
`src/web-components/furo-ui5-<name>/` contains:
- `FuroUi5<Name>.ts` — extends the UI5 element (e.g. `extends Input`), composes a small set of helper classes from `src/lib/open-models/`, exposes `bindData(fieldNode)` plus a `model` getter/setter, and re-emits UI5 events as needed.
- `index.ts` — calls `FuroUi5<Name>.define()` and augments `HTMLElementTagNameMap`. This is the file consumers import for side-effect registration.

The helper classes wire a component to `@furo/open-models`:
- `ModelReaderWriter` — dispatches by `fieldNode.__meta.typeName` to a typed reader/writer pair (see `StringReaderWriters`, `NumericReaderWriters`, `BoolReaderWriters`); add a new type binding here.
- `FatHandler<T>` — maps FAT `attributes` (e.g. `placeholder`, `maxlength`, `value-state`) onto component properties. Each component lists which FAT attributes it accepts in the constructor: `new FatHandler(this, ["placeholder", "maxlength"])`. Labels `hidden|readonly|disabled|required` are honored by default.
- `FieldNodeValueState` / `ReadonlyState` — synchronize UI5 value-state and readonly flags with the field node's state.

When adding a component, mirror an existing one (e.g. `furo-ui5-text-input`), export it from `src/index.ts`, and register its `furo-ui5-*` tag in `src/Assets.ts`-adjacent registration if it must always be loaded.

### Generated code (do not hand-edit)
- `src/JSX/*` — regenerated by `npm run gen:intrinsic` from the CEM. Eslint ignores this directory; if a build complains here, re-run the generator.
- `src/models/*` — regenerated by `npm run gen:contracts` from `.proto`. Both eslint and `tsconfig` paths treat these as generated;
- `dist/`, `custom-elements.json`, `web-types.json` — produced by `npm run build`.

### Type renderers
`src/type-renderers/` ships display/edit/form/cell/celledit components per Furo and Google well-known type (e.g. `display-google-protobuf-timestamp.ts`). They are **excluded from `tsconfig.json` and eslint** and are bundled separately via `analyze:deep`. Build issues here won't surface during `tsc` — run the full build to validate.

### Path alias
`@/*` resolves to `src/*` (tsconfig + vite). After `tsc`, `tsc-alias` rewrites these to relative paths in `dist/`. Use `@/...` in source, never relative-up-out-of-src.

### Testing
Tests run inside Chromium with `slowMo: 100` and devtools enabled. They use `@open-wc/testing-helpers` `fixture` + Lit `html`, vitest's `LocatorSelectors`, and `chai-a11y-axe` for a11y assertions (`await assert.isAccessible(el)`). Each test file imports `@/Assets` plus the component's `index` to trigger registration. JUnit output lands in `test-results/junit.xml`; coverage is off by default (toggle in `vite.config.ts`).

### Peer dependencies & local linking
`@furo/layout` is pinned to a local `.tgz` path under `/Users/veith/Projects/theNorstroem/eclipsefuro-web/...` — `npm install` will fail on machines without that file. `npm run bootstrap` does `npm install && npm link && npm link @furo/ui5` for cross-package development against sibling Furo packages.

## Lint rules worth knowing

- `eslint-plugin-lit` is in `flat/all` mode (very strict), `eslint-plugin-wc` in `flat/best-practice`. `lit/quoted-expressions` requires `"always"`.
- `@typescript-eslint/no-explicit-any` is `error` — there is no escape hatch beyond `unknown` + narrowing.
- Lifecycle methods (`connectedCallback`, `firstUpdated`, `render`, `update`, `updated`, the `onPage*` route hooks, etc.) are whitelisted for `class-methods-use-this`.
- Imports use `import-x/order` with alphabetized groups and `newlines-between: always`.
- `src/stories/**`, `dist/**`, `src/type-renderers/**`, `src/models/**`, and `src/x/models/**` are eslint-ignored.
